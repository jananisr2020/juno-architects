# Contributing

## Workflow
1. Keep Juno Architects separate from Juno Fashion/Threadly.
2. Use a focused branch and pull request for meaningful feature work.
3. Update documentation and the roadmap when behavior or architecture changes.
4. Add tests for calculations, validation, and geometry rules.
5. Run `npm test` and `npm run build` before merging frontend changes.
6. Never mark a task done without implementation and verification evidence.

## Engineering principles
- TypeScript strict mode stays enabled.
- Keep pricing assumptions out of view components.
- Add provenance and effective dates before presenting regional rates as verified.
- Keep AI-generated proposals separate from deterministic validation.
- Prefer semantic HTML, keyboard access, mobile layouts, and readable error messages.
- Keep dependencies minimal and review updates.

## Commit messages
Use concise prefixes such as `feat:`, `fix:`, `test:`, `docs:`, and `chore:`.
